# Usability Test Plan

Status: tasks prepared; no participant feedback is claimed until real sessions are completed.

Use 3–5 representative participants when available. Do not coach them through the interface unless they are blocked; record the blockage instead.

## Tasks

1. Sign in, find **My profile**, and explain how they would recover a forgotten password.
2. As an operational user, create a campaign and add one day of performance data.
3. Filter Overview to that campaign/date and interpret one KPI and its trend.
4. Compare two campaigns or channels in Analytics, then find or create a KPI target if their role permits it.
5. Preview a report and download the PDF.
6. For an Administrator or Marketing Officer, import the provided CSV fixture through preview, mapping, validation, and confirmation.

## Observations to record

For each participant record only a participant code and relevant experience level, then capture:

- task completed without help: yes/no
- time or major delay point
- navigation or wording that caused confusion
- validation/error message understood: yes/no/not encountered
- keyboard/mobile issue if observed
- severity: blocker, significant, minor, suggestion
- participant's own short comment
- proposed follow-up, if any

Do not record passwords, tokens, or unnecessary personal information.

## Acceptance review

After sessions, group repeated findings and decide which are release blockers. Update the implementation evidence with actual participant count, dates, results, and resulting fixes. Until then, participant availability remains an external evidence dependency.
