## Implementation and policy

- PDFKit restores the text cursor after its vector chart, bounds wrapped rows to page margins, shows isolated points across null gaps, and explains single/missing trends. Three PDF.js tests parse actual rendered output for values/units/targets/Unicode, vector paths, text bounds, long-report pagination and retained final content. [ADR-008](../decisions/ADR-008-pdfkit-reports.md) records deployment/font tradeoffs.
- Twenty-five new real HTTP authorization/read/logout cases complement the existing metadata matrix. Anonymous and wrong-role callers are rejected; permitted callers must supply valid Origin and CSRF values. Denied writes leave all non-session application-table fingerprints unchanged. Expected session last-seen updates are excluded; logout/password-change revocation is checked separately.
- The Windows integration runner now invokes Prisma/tsx/Vitest directly with Node instead of spawning a `.cmd` file. Scripts are included in formatting/type checks and excluded from production output; `dist/src/main.js` remains the entrypoint.
- CI uses PostgreSQL 18 and matching client tools. Artifacts are explicitly limited to non-sensitive load/restore summaries; credentials, database dumps and environment files are excluded.
- [Both existing policy decisions](../governance/completion-decisions-2026-10-07.md) were explicitly approved by the stakeholder during this follow-up. Their earlier AI implementation does not establish an earlier approval date.

## Load results and limitations

The fixture adds ten campaigns, 300 daily records and 600 metric values. Twenty-five independent users include five Marketing Officers with permitted raw corrections and twenty read-only Management users. A separate phase measures PDF export. The baseline assumes one view per action, 1.5-second think time and a 40/20/20/20 dashboard/trends/campaign/performance mix. These assumptions are not participant observations or stakeholder SLAs.

Earlier runs are retained as findings:

- The initial harness lost its cookie session between k6 iterations. Added `noCookiesReset`; no application protection was weakened.
- A four-view burst profile with 0.5-second think time had 479 requests, zero request failures and p95 6.93 seconds. It did not meet the one-second local evaluation target and does not establish burst capacity. Its run also overlapped local verification activity.
- The one-view baseline had 445 requests at 14.12 requests/second, median 50.82 ms and p95 725.05 ms, with zero failures. The maximum was 10.18 seconds, so tail/startup latency remains a limitation even when p95 passes.
- The separate cold PDF phase had 24 requests, zero failures, median 259.62 ms, p95 1,065.20 ms and maximum 2,019.68 ms. It missed the one-second target. The final harness explicitly records a separate PDF warm-up before measured export; its cold latency is retained rather than reclassified as a passing measured result.

Measured mixed/PDF phases retain p95 below one second, request errors below 1%, and successful checks above 99%. Warm-up latency is reported separately. The final four-phase run completed successfully at `2026-10-07T19:52:33.389Z`: measured mixed had 535 requests at 17.04 requests/second, median 19.61 ms, p95 295.47 ms and maximum 2,656.69 ms; measured PDF had 30 requests, median 162.97 ms, p95 227.76 ms and maximum 370.28 ms. Both had zero failures and 100% successful checks. Separate PDF warm-up had 12 requests and p95 387.01 ms. Source fixtures and temporary credentials were removed, and the temporary API stopped. The non-sensitive ignored `performance/runtime/load-evidence.json` retains all four phase summaries. Short local warmed measurements do not establish cold-start, burst or production capacity.
